## 1. AIVerdict Model

**Location:** `backend/models/AIVerdict.js`

### Purpose
Stores the AI-generated fact-checking verdict for a news article, including the credibility score, analysis text, and the top comments that influenced the decision.

### Complete Schema

```javascript
const mongoose = require('mongoose');

const aiVerdictSchema = new mongoose.Schema({
  
  // ═══════════════════════════════════════════════════════════════
  // NEWS RELATIONSHIP
  // ═══════════════════════════════════════════════════════════════
  
  newsId: {
    type: mongoose.Schema.Types.ObjectId,
    ref: 'News',
    required: true,
    unique: true  // IMPORTANT: Only ONE verdict per news article!
  },
  // WHY: Link verdict to its news article
  // WHAT: ObjectId of the news being analyzed
  // UNIQUE: Prevents multiple verdicts for same news
  // 
  // If you try to create second verdict for same news:
  //   Error: "E11000 duplicate key error"
  //
  // To update: Use findOneAndUpdate or regenerateVerdict()
  
  
  // ═══════════════════════════════════════════════════════════════
  // THE VERDICT
  // ═══════════════════════════════════════════════════════════════
  
  verdict: {
    type: String,
    required: true,
    maxlength: 2000  // ~250 words of detailed analysis
  },
  // WHY: Human-readable AI analysis
  // WHAT: Detailed explanation of why news is real/fake
  // HOW: Generated by Gemini AI function calling
  //
  // EXAMPLE:
  // "Based on analysis of 15 comments including 3 expert opinions,
  //  this article appears to be PARTIALLY MISLEADING. While the 
  //  core claim about coffee health benefits is supported by 
  //  peer-reviewed studies (referenced by @dr_jane), the specific
  //  statistics cited are exaggerated. The original study showed
  //  a 5% reduction in risk, not the 50% claimed..."
  
  score: {
    type: Number,
    required: true,
    min: 0,
    max: 100  // Scale: 0 = definitely fake, 100 = definitely real
  },
  // WHY: Quantifiable credibility metric
  // WHAT: Credibility score on 0-100 scale
  // HOW: Calculated by AI based on evidence and expert consensus
  //
  // INTERPRETATION:
  //   0-20:   Likely Fake / Misleading
  //   21-40:  Questionable / Needs Verification
  //   41-60:  Uncertain / Mixed Evidence
  //   61-80:  Likely Accurate / Mostly True
  //   81-100: Highly Credible / Verified
  
  confidence: {
    type: Number,
    required: true,
    min: 0,
    max: 1  // 0.0 = no confidence, 1.0 = fully confident
  },
  // WHY: Indicate AI's certainty in the verdict
  // WHAT: How confident the AI is in its analysis
  // HOW: Based on amount/quality of evidence
  //
  // LOW CONFIDENCE (< 0.5):
  //   - Few comments
  //   - No expert input
  //   - Conflicting evidence
  //
  // HIGH CONFIDENCE (> 0.8):
  //   - Multiple expert comments
  //   - Strong evidence links
  //   - Clear consensus
  
  
  // ═══════════════════════════════════════════════════════════════
  // TOP COMMENTS (Evidence for the verdict)
  // ═══════════════════════════════════════════════════════════════
  
  topComments: {
    // Comments supporting the news claim
    inFavor: [{
      commentId: {
        type: mongoose.Schema.Types.ObjectId,
        required: true
      },
      commentType: {
        type: String,
        enum: ['community', 'expert'],
        required: true
      },
      commentText: {
        type: String,
        required: true
      },
      evidenceLinks: [{
        url: String,
        explanation: String
      }],
      upvoteCount: {
        type: Number,
        default: 0
      },
      downvoteCount: {
        type: Number,
        default: 0
      },
      score: {
        type: Number,
        default: 0  // upvotes - downvotes
      }
    }],
    
    // Comments against the news claim
    against: [{
      commentId: {
        type: mongoose.Schema.Types.ObjectId,
        required: true
      },
      commentType: {
        type: String,
        enum: ['community', 'expert'],
        required: true
      },
      commentText: {
        type: String,
        required: true
      },
      evidenceLinks: [{
        url: String,
        explanation: String
      }],
      upvoteCount: {
        type: Number,
        default: 0
      },
      downvoteCount: {
        type: Number,
        default: 0
      },
      score: {
        type: Number,
        default: 0
      }
    }]
  },
  // WHY: Store the most influential comments
  // WHAT: Top comments from each stance
  // HOW: Selected by aiVerdictService.selectTopComments()
  //
  // SELECTION CRITERIA (in order of priority):
  //   1. Expert comments weighted higher than community
  //   2. Comments with evidence links ranked higher
  //   3. Higher vote scores preferred
  //   4. Limited to top 5 per stance
  //
  // WHY STORE FULL COMMENT DATA?
  //   - Snapshot at time of verdict (comments can change later)
  //   - Faster display (no population needed)
  //   - Audit trail of what influenced decision
  
  
  // ═══════════════════════════════════════════════════════════════
  // ANALYSIS METADATA (Statistics)
  // ═══════════════════════════════════════════════════════════════
  
  analysisMetadata: {
    totalCommentsAnalyzed: {
      type: Number,
      default: 0
    },
    // How many comments were considered
    // Example: 47
    
    commentsByStance: {
      inFavor: { type: Number, default: 0 },
      against: { type: Number, default: 0 },
      general: { type: Number, default: 0 }
    },
    // Distribution of comment stances
    // Example: { inFavor: 15, against: 27, general: 5 }
    // This shows more opposition → lower credibility score
    
    averageScore: {
      inFavor: { type: Number, default: 0 },
      against: { type: Number, default: 0 }
    }
    // Average vote score by stance
    // Example: { inFavor: 3.2, against: 7.8 }
    // Higher against score → community agrees with opposition
  },
  // WHY: Transparency in AI decision
  // WHAT: Statistics about the analysis
  // HOW: Calculated by aiVerdictService.calculateMetadata()
  //
  // USAGE:
  //   - Display "Based on analysis of 47 comments..."
  //   - Show stance breakdown in chart
  //   - Explain why verdict was reached
  
  
  // ═══════════════════════════════════════════════════════════════
  // TIMESTAMPS
  // ═══════════════════════════════════════════════════════════════
  
  createdAt: {
    type: Date,
    default: Date.now
  },
  // When verdict was first generated
  
  lastRegenerated: {
    type: Date,
    default: Date.now
  },
  // When verdict was last updated
  // Different from createdAt if regenerated
  
  
  // ═══════════════════════════════════════════════════════════════
  // AI MODEL INFO
  // ═══════════════════════════════════════════════════════════════
  
  generatedBy: {
    model: {
      type: String,
      default: 'gemini-3-flash-preview'
    },
    version: {
      type: String,
      default: '1.0'
    }
  }
  // WHY: Track which AI model was used
  // WHAT: Model name and version
  // HOW: Useful for debugging, comparisons, auditing
  //
  // If AI behavior changes, can trace to model version
});


// ═══════════════════════════════════════════════════════════════
// INDEXES
// ═══════════════════════════════════════════════════════════════

aiVerdictSchema.index({ newsId: 1 });
// Fast lookup by news: AIVerdict.findOne({ newsId: newsId })

aiVerdictSchema.index({ createdAt: -1 });
// Fast sorting by newest: AIVerdict.find().sort({ createdAt: -1 })

const AIVerdict = mongoose.model('AIVerdict', aiVerdictSchema);

module.exports = AIVerdict;
```

### AIVerdict Generation Flow

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       AI VERDICT GENERATION FLOW                            │
└─────────────────────────────────────────────────────────────────────────────┘

Trigger: Manual request or automatic after threshold

Step 1: Collect All Comments
────────────────────────────
  const expertComments = await ExpertComment.find({ newsId });
  const communityComments = await CommunityComment.find({ newsId });
  
  Total: 47 comments


Step 2: Select Top Comments (aiVerdictService.selectTopComments)
────────────────────────────────────────────────────────────────
  Priority scoring:
    Expert comment: +10 base
    Community comment: +5 base
    Has evidence links: +3 per link
    Vote score: +(upvotes - downvotes)
  
  Sort by priority, take top 5 per stance:
    inFavor: [expertComment1, communityComment4, ...]
    against: [expertComment2, communityComment1, ...]


Step 3: Calculate Metadata
──────────────────────────
  analysisMetadata: {
    totalCommentsAnalyzed: 47,
    commentsByStance: {
      inFavor: 15,
      against: 27,
      general: 5
    },
    averageScore: {
      inFavor: 3.2,
      against: 7.8
    }
  }


Step 4: Call AI (aiVerdictService.callAIForVerdict)
──────────────────────────────────────────────────
  Input to Gemini:
  {
    newsTitle: "Coffee Study Shows 50% Health Improvement",
    newsDescription: "A new study claims...",
    topCommentsInFavor: [...],
    topCommentsAgainst: [...],
    metadata: {...}
  }
  
  Gemini Function Call: generate_news_verdict({
    verdict_text: "Based on analysis...",
    credibility_score: 35,
    confidence_level: 0.82,
    key_factors: [...]
  })


Step 5: Save AIVerdict
──────────────────────
  AIVerdict.create({
    newsId: newsId,
    verdict: "Based on analysis...",
    score: 35,
    confidence: 0.82,
    topComments: { inFavor: [...], against: [...] },
    analysisMetadata: {...},
    generatedBy: { model: 'gemini-3-flash-preview', version: '1.0' }
  })


Step 6: Update News Status
──────────────────────────
  if (score <= 40) {
    news.status = 'Fake';
  } else if (score >= 70) {
    news.status = 'Verified';
  }
  // If 41-69: stays 'Pending' (needs more evidence)
```

## 2. CommentFilter and CommentGroup Models

**Location:** `backend/models/CommentFilter.js`

### Purpose
These models support AI-powered comment grouping:
- **CommentFilter**: Processed comments ready for grouping
- **CommentGroup**: Groups of similar comments with labels

### Why Group Comments?

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       WHY GROUP COMMENTS?                                   │
└─────────────────────────────────────────────────────────────────────────────┘

WITHOUT GROUPING (Raw comments):
─────────────────────────────────
  Comment 1: "The sample size is too small"
  Comment 2: "I don't trust this source"
  Comment 3: "50 participants isn't enough for conclusions"
  Comment 4: "This contradicts WHO guidelines"
  Comment 5: "My friend tried it and it worked"
  Comment 6: "The study methodology is questionable"
  Comment 7: "Check the sample size - only 50 people"
  ...47 more comments...

  Problem: 
    - User overwhelmed by similar points
    - Hard to see main arguments
    - Repetitive reading


WITH GROUPING (AI-organized):
─────────────────────────────
  📁 Group: "Sample Size Concerns" (3 comments)
     ├─ Comment 1: "The sample size is too small"
     ├─ Comment 3: "50 participants isn't enough..."
     └─ Comment 7: "Check the sample size - only 50 people"
  
  📁 Group: "Methodology Critiques" (2 comments)
     ├─ Comment 6: "The study methodology is questionable"
     └─ Comment 12: "No control group mentioned"
  
  📁 Group: "Source Credibility" (1 comment)
     └─ Comment 2: "I don't trust this source"
  
  📁 Group: "Anecdotal Evidence" (1 comment)
     └─ Comment 5: "My friend tried it and it worked"

  Benefits:
    ✓ Clear argument categories
    ✓ Easy to see main points
    ✓ Similar comments consolidated
    ✓ Better understanding of debate
```

### CommentFilter Schema

```javascript
const mongoose = require('mongoose');
const { Schema } = mongoose;

const CommentFilterSchema = new Schema({
  
  // ═══════════════════════════════════════════════════════════════
  // COMMENT DATA
  // ═══════════════════════════════════════════════════════════════
  
  text: { 
    type: String, 
    required: true 
  },
  // WHY: Store comment text for AI processing
  // WHAT: Copy of original comment text
  // HOW: Copied when comment is processed for filtering
  
  originalCommentId: {
    type: Schema.Types.ObjectId,
    required: true
  },
  // WHY: Link back to original comment
  // WHAT: ObjectId of CommunityComment or ExpertComment
  // HOW: Used to update original with filterGroupId
  // NOTE: Not using ref because could be either comment type
  
  commentType: {
    type: String,
    enum: ['community', 'expert'],
    required: true
  },
  // WHY: Know which collection to look in
  // WHAT: Type of the original comment
  // HOW: Determines reference collection for originalCommentId
  
  newsId: {
    type: Schema.Types.ObjectId,
    ref: 'News',
    required: true
  },
  // WHY: Link to parent news
  // WHAT: ObjectId of the news article
  // HOW: Query all filtered comments for a news
  
  
  // ═══════════════════════════════════════════════════════════════
  // AI PROCESSING
  // ═══════════════════════════════════════════════════════════════
  
  embedding: { 
    type: [Number], 
    default: [] 
  },
  // WHY: Store vector representation of comment
  // WHAT: Semantic embedding (e.g., 768 numbers)
  // HOW: Generated by embedding model or LLM
  //
  // USAGE:
  //   - Calculate similarity between comments
  //   - Find comments with similar meaning
  //   - Cluster related comments together
  //
  // EXAMPLE: [0.123, -0.456, 0.789, ..., 0.234] (768 numbers)
  //
  // NOTE: Currently may be empty if not using embeddings
  //       LLM-based classification is used instead
  
  groupId: { 
    type: Schema.Types.ObjectId, 
    ref: 'CommentGroup', 
    default: null 
  },
  // WHY: Track which group this comment belongs to
  // WHAT: Reference to assigned CommentGroup
  // HOW: Set by AI classification
  // NULL: Not yet classified
  
  createdAt: { 
    type: Date, 
    default: Date.now 
  }
});

const CommentFilter = mongoose.model('CommentFilter', CommentFilterSchema);
```

### CommentGroup Schema

```javascript
const CommentGroupSchema = new Schema({
  
  // ═══════════════════════════════════════════════════════════════
  // GROUP IDENTITY
  // ═══════════════════════════════════════════════════════════════
  
  label: { 
    type: String, 
    required: true 
  },
  // WHY: Short identifier for the group
  // WHAT: Brief label for the category
  // HOW: Generated by AI (llmService.generateGroupDescription)
  // EXAMPLE: "Sample Size Concerns", "Scientific Evidence"
  
  description: {
    type: String,
    default: ''
  },
  // WHY: Explain what this group contains
  // WHAT: Longer description of the group theme
  // HOW: AI-generated summary of common points
  // EXAMPLE: "Comments in this group express concerns about
  //           the small sample size of the study and its
  //           implications for statistical validity."
  
  
  // ═══════════════════════════════════════════════════════════════
  // RELATIONSHIP
  // ═══════════════════════════════════════════════════════════════
  
  newsId: {
    type: Schema.Types.ObjectId,
    ref: 'News',
    required: true
  },
  // WHY: Link group to its news article
  // WHAT: ObjectId of the news
  // HOW: Query all groups for news: { newsId: newsId }
  
  comments: [{ 
    type: Schema.Types.ObjectId, 
    ref: 'CommunityComment'  // Note: Only references CommunityComment
  }],
  // WHY: Track which comments are in this group
  // WHAT: Array of comment ObjectIds
  // HOW: Populated for display
  // NOTE: Could also include ExpertComment references
  
  
  // ═══════════════════════════════════════════════════════════════
  // AI PROCESSING
  // ═══════════════════════════════════════════════════════════════
  
  embedding: { 
    type: [Number], 
    default: [] 
  },
  // WHY: Group centroid for similarity matching
  // WHAT: Average embedding of all comments in group
  // HOW: Used to match new comments to existing groups
  //
  // MATCHING PROCESS:
  //   1. New comment comes in
  //   2. Calculate its embedding
  //   3. Compare to all group embeddings
  //   4. If similarity > threshold → add to group
  //   5. If no match → create new group
  
  createdAt: { 
    type: Date, 
    default: Date.now 
  }
});

const CommentGroup = mongoose.model('CommentGroup', CommentGroupSchema);

module.exports = { CommentFilter, CommentGroup };
```

## Interview Questions & Answers

### Q1: Why is newsId unique in AIVerdict?
**Answer:** Each news article should have exactly one verdict:
1. **Consistency**: Users see one definitive AI opinion
2. **Updates**: Regeneration updates existing verdict, doesn't create new
3. **Performance**: No need to check for multiple verdicts
4. **Data integrity**: Prevents duplicates from race conditions

To update a verdict, use `findOneAndUpdate` or `regenerateVerdict()`.

### Q2: Why store full comment data in topComments instead of just ObjectIds?
**Answer:** Snapshot approach for:
1. **Historical accuracy**: Comments can be edited/deleted later
2. **Performance**: No population needed for display
3. **Audit trail**: Know exactly what AI analyzed
4. **Consistency**: Verdict + evidence stay in sync

Trade-off: Data duplication, but worth it for reliability.

### Q3: How does confidence differ from score?
**Answer:**
- **Score (0-100)**: How credible is the NEWS? (Real vs Fake)
- **Confidence (0-1)**: How confident is the AI in its verdict?

Example scenarios:
- Score: 80, Confidence: 0.9 → "Probably real, and we're pretty sure"
- Score: 80, Confidence: 0.4 → "Probably real, but we need more evidence"
- Score: 30, Confidence: 0.95 → "Definitely fake, very confident"

### Q4: What's the difference between CommentFilter and the original Comment?
**Answer:**
| CommentFilter | Original Comment |
|---------------|------------------|
| For AI processing | Full comment data |
| Has embeddings | Has votes, evidence |
| Links to groups | Links to news |
| Temporary/processing | Permanent record |

CommentFilter is a processing layer that doesn't replace original comments.

### Q5: Why use LLM classification instead of embeddings for grouping?
**Answer:** Trade-offs:
- **Embeddings**: Faster, more consistent, requires embedding model
- **LLM Classification**: More nuanced, understands context, slower, costs more

VoxVeritas uses LLM classification because:
1. Better semantic understanding
2. Can generate group descriptions
3. Handles edge cases better
4. Already using Gemini for other features
