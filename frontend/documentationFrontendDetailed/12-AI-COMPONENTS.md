## 1. What Is the AI Verdict?

The AI Verdict is a **comprehensive credibility analysis** of a news article generated by Google's Gemini AI. Unlike the simple ML-based "REAL/FAKE" classification (shown in the NewsCard's AI Analysis section), the AI Verdict provides:

- A **credibility score** (0–100)
- A **detailed explanation** of why the article is/isn't credible
- Analysis of sources, claims, and evidence

## 4. The Credibility Score System

### 4.1 — Helper Functions

```jsx
// Color based on score:
const getScoreColor = (score) => {
  if (score >= 70) return 'text-green-600';   // Good
  if (score >= 40) return 'text-yellow-600';  // Mixed
  return 'text-red-600';                      // Bad
};

// Background gradient for score bar:
const getScoreBackground = (score) => {
  if (score >= 70) return 'bg-gradient-to-r from-green-500 to-green-600';
  if (score >= 40) return 'bg-gradient-to-r from-yellow-500 to-yellow-600';
  return 'bg-gradient-to-r from-red-500 to-red-600';
};

// Human-readable label:
const getCredibilityLabel = (score) => {
  if (score >= 80) return 'Highly Credible';
  if (score >= 60) return 'Likely Credible';
  if (score >= 40) return 'Mixed Evidence';
  if (score >= 20) return 'Likely False';
  return 'Highly Suspicious';
};
```

## 6. The Generate / Regenerate Flow

### 6.1 — First-Time Generation

```jsx
const generateVerdict = async () => {
  setGenerating(true);
  setError(null);
  try {
    const response = await aiVerdictAPI.generateVerdict(newsId);
    // POST /api/news/{newsId}/ai-verdict
    //
    // Backend journey:
    //   1. Fetch news article from database
    //   2. Send article text to Gemini API with analysis prompt
    //   3. Gemini returns credibility score + explanation
    //   4. Store verdict in database
    //   5. Return verdict to frontend

    if (response.success) {
      setVerdict(response.data);
      setShowVerdict(true);     // Auto-expand to show the result
      toast.success('AI verdict generated successfully!');
      onVerdictUpdate?.(response.data);  // Notify parent
    }
  } catch (error) {
    const msg = error.response?.data?.message || 'Failed to generate AI verdict';
    setError(msg);
    toast.error(msg);
  } finally {
    setGenerating(false);
  }
};
```

### 6.2 — Regeneration

```jsx
const regenerateVerdict = async () => {
  // Same as generate but uses PUT instead of POST
  // PUT /api/news/{newsId}/ai-verdict/regenerate
  // Overwrites existing verdict with fresh AI analysis
  // Useful when article has been updated or new information is available
  setGenerating(true);
  try {
    const response = await aiVerdictAPI.regenerateVerdict(newsId);
    if (response.success) {
      setVerdict(response.data);
      toast.success('AI verdict regenerated!');
      onVerdictUpdate?.(response.data);
    }
  } catch (error) {
    toast.error('Failed to regenerate');
  } finally {
    setGenerating(false);
  }
};
```

## 7. Interview Q&A

**Q: Why does AIVerdictSection check for an existing verdict on mount?**
A: The verdict is stored in the database. If another user already generated a verdict for this article, we want to display it without requiring every user to generate their own. The mount check (`checkExistingVerdict`) fetches any pre-existing verdict.

**Q: Why have both Generate and Regenerate?**
A: Generate (POST) creates a new verdict — it will fail if one already exists. Regenerate (PUT) overwrites an existing verdict with a fresh analysis. This separation is an API design pattern that prevents accidental overwrites.

**Q: Why might the AI verdict change on regeneration?**
A: AI models like Gemini can produce different outputs for the same input due to temperature/randomness settings. Also, the backend might rotate between different Gemini API keys (to avoid rate limits), and the underlying model may have been updated.

**Q: Why are the score thresholds different between getScoreColor and getCredibilityLabel?**
A: They serve different purposes. `getScoreColor` uses 3 buckets (green/yellow/red) for quick visual feedback. `getCredibilityLabel` uses 5 buckets for more precise textual description. The different threshold values reflect that color perception needs fewer categories than text.
